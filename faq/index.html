    FAQ¶

    Short answers to the questions that come up most. Each links to the page with the full story.

    Is this the only "right" way to do things? No. It's a working solution. The genuinely required rules are short (never overwrite raw data; commit-to-share; one writer per file; exhibits trace to code); everything else — the exact layout, Dropbox, Overleaf, the tools — is a recommendation you can adapt. → required vs. recommended

    Do I need to know git? No — you can pick it up gradually. Claude Code (or GitHub Desktop) handles the mechanics, and the primer defines every term in plain language.

    Do I need Claude Code / an AI tool at all? No. Everything works by hand — Claude is a convenience, never a dependency. → the manual workflow, choosing your setup

    Do I need Dropbox? Do I need Overleaf? Dropbox is the recommended default (backup + sharing), but a pure-GitHub setup works too. Overleaf is usually not needed — everything compiles locally; its one real draw is track-changes review of prose. → choosing your setup, new to Overleaf?

    Who's the lead / who's in charge? Nobody — it's leaderless. Every co-author is equal; main lives on GitHub, owned by no one; anyone can push and merge. → why collaboration is hard

    Where's the latest paper? Which clone has it? The canonical version is main on GitHub. On team projects, the shared container also keeps a read-only copy of the current paper so you never have to hunt through clones. → what goes where

    What if I mess up or lose work? Almost nothing here is unrecoverable if you stop and ask before improvising — git history and Dropbox both back you up. → common issues

    How do I actually run a skill? Three ways: a slash command (/name), just describe the task in plain language, or let it auto-trigger (a nudge, not a guarantee). → how skills are triggered

    How do I set up a new — or existing — project? New: /bootstrap-project. Existing/messy: back up first, then /refactor-structure. → what goes where → "turning a messy project into this"

    How do I update the toolkit later? /plugin marketplace update kai-team-claude + restart Claude Code; re-run the install script for the ~/.claude skills. → install the toolkit, updates

    Is my data safe? data/raw/ is read-only — never overwritten; data/processed/ is rebuildable from raw + code. There's even a guard that asks before any code writes to raw. → working with the shared data

    Where do I read these docs / is this online? Yes — the hosted site is at kaligi.github.io/kai-team-claude-docs (search + sidebar; nothing to install, just open the link). The editable source lives in the private GitHub repo under docs/ (ask Kai for an invite). The website is auto-published from there into a separate public repo that contains only the built HTML — so the page is public even though the toolkit's source isn't. You read on the website; you install the toolkit from the private repo (Install).
