    Install the Claude Code toolkit¶

    Why bother. This is what turns Claude Code from a generic assistant into one that knows economics-paper conventions — drafting in your voice, referee reports, figures from real data, citation hygiene. If that payoff isn't worth a one-time setup to you yet, skip it; the collaboration workflow works without it. (New to what "skills", "plugins", and "the marketplace" mean? Read what the toolkit is first — two minutes.)

    This is the optional toolkit install: Claude Code + the Zotero bridge + the plugin marketplace, so you get the writing helpers, review pipelines, and figure tools. If you only want to work on a shared paper (git + your stats software), you do not need this — see the co-author quickstart instead.

    Assumes no command-line experience: every step is copy-paste. Stuck? Ask whoever set you up, or open an issue on the repo, with the exact error text + the step number.

    What you'll have when you're done¶

    Once setup is finished, in any terminal you can type claude to start a Claude Code session. Inside that session you can:

    • Type /academic to launch a multi-agent review of a paper or chapter
    • Type /review-paper to get a 6-agent referee report on a draft
    • Type /review-paper-light for a fast 2-agent contribution-and-identification check
    • Type /bootstrap-project on day 1 of a new project to scaffold a CLAUDE.md and working/ folder
    • Ask Claude to "draft this paragraph in Kai's style" → the kai-writing skill kicks in
    • Ask Claude to search Zotero for a paper, fetch the BibTeX, and add it to the project's bib file
    • Ask Claude to draft a TikZ diagram, build a real-data figure, or design a seminar talk
    • Ask Claude to help turn open-ended survey answers into validated variables → the qualitative-survey-coding skill kicks in

    You'll also have access to the project's shared folders (Dropbox, GitHub, Overleaf, Zotero group library) once those per-project invitations are sent.

    The toolkit covers the whole research pipeline — each stage has its tools (every name below is in the toolkit index; the chains are in recipes):

    flowchart LR
    A["Start project<br/>/bootstrap-project"] --> B["Get data<br/>data-catalog"]
    B --> C["Analyze<br/>/data-analysis &#183; /stata-replication"]
    C --> D["Figures & tables<br/>real-data-figure &#183; /coef-plot<br/>/build-fragment-table"]
    D --> E["Write<br/>kai-writing &#183; /academic"]
    E --> F["Pre-submission<br/>/review-paper-light &#8594; /review-paper<br/>bib-audit &#183; audit-reproducibility"]
    F --> G["Replication package<br/>init-replication &#183; /audit-exhibits"]

    E -.-> I["Grants<br/>/review-grant"]

    Step-by-step install¶

    Budget 60–90 minutes the first time. You only do it once per laptop.

    Step 0 — Things you need before starting¶

    A terminal. This is just a window where you type commands. - Windows: press Win key, type "Terminal", open the app called "Terminal" (or "Windows Terminal"). It opens in PowerShell by default — that's what we'll use. - macOS: press Cmd+Space, type "Terminal", press Enter. - Linux: you already know.

    The three lines above are all you need to open a terminal — you don't need to know the difference between "Terminal" and "PowerShell"; either is fine. If the command line is genuinely new and you'd like a gentle 10-minute tour of the handful of commands you'll see (cd, ls, pwd, pasting safely, reading an error), terminal in 10 minutes is there — optional, but it takes the nerves out of every step below.

    About admin / root permissions. The install does not require admin / root privileges as a whole. The only step that might prompt for it is npm install -g on macOS/Linux, and Step 1 below tells you how to handle that. On Windows, leave "Add to PATH" ticked in the Node installer and pick "Install for me only" (not "all users") — that avoids any admin prompt.

    An Anthropic account with Claude.ai access. Sign up at https://claude.ai/. The Pro plan (currently around 20 USD/month) is enough for normal academic use; the Max plan if you'll run many long sessions. If your team has a shared plan, ask whoever manages it about being added instead of paying personally.

    Python 3 (only needed for a couple of plugin hooks, not Claude Code itself). Most macOS/Linux machines already have it; on Windows, install from https://www.python.org/ (tick "Add to PATH") or via Anaconda. Check with python3 --version (or python --version). Any recent 3.x is fine.

    A GitHub account, and someone must have invited your GitHub username to the repository. Whoever set up your team's access does this — it doesn't have to be any particular person. Confirm you've accepted the invite before Step 4; without it, Step 4 fails with "repository not found".

    Git itself. Windows: install Git for Windows from https://git-scm.com (accept all defaults — this also gives you "Git Bash", a terminal where every command in our docs works). macOS: open Terminal, type git --version; if a pop-up offers to install developer tools, click Install. Without this, Step 4 fails with "git is not recognized".

    (Optional) The GitHub CLI for easier GitHub auth. Install from https://cli.github.com. Then run gh auth login once and HTTPS clones won't ask for a password. Skip this if you already use GitHub Desktop or have an SSH key set up.

    Step 1 — Install Node.js and Claude Code¶

    Claude Code is the command-line tool from Anthropic that everything else runs on top of. It needs Node.js.

    1. Open https://nodejs.org/ and click the "LTS" download button (currently 20.x or 22.x — either works). Run the installer. On Windows, leave "Add to PATH" ticked.
    2. Close and reopen your terminal so it sees the new Node.
    3. Verify Node is installed: 
      node --version
      Should print something like v20.18.0.
    4. Install Claude Code: 
      npm install -g @anthropic-ai/claude-code
    5. macOS / Linux: if you see EACCES (permission denied), either rerun with sudo (sudo npm install -g @anthropic-ai/claude-code) OR follow the npm prefix instructions at https://docs.npmjs.com/resolving-eacces-permissions-errors-when-installing-packages-globally.
    6. Windows: should just work; if you see "is not recognized", close and reopen the terminal so Windows picks up the new PATH.
    7. Verify: 
      claude --version

    Step 2 — Sign in to Claude Code¶

    1. In the terminal, type claude and press Enter.
    2. The first time, it will ask you to sign in. A browser window will pop open. Sign in with the same Anthropic account you used in Step 0. (If you're on a remote machine without a browser, copy the URL it prints and open it on your laptop.)
    3. After the browser shows "success", come back to the terminal — it should say you're signed in.
    4. Type /quit and press Enter to exit. We'll come back later.

    Step 3 — Install Zotero and the Zotero MCP server¶

    Most people should skip this on the first pass. Zotero powers citation search and bib Path 3 — nothing else. If you're new, or you mainly run Stata/R, or you just want to get going: skip to Step 4 now and come back only if/when you want Zotero-driven citations. (It's also the step most likely to blow the time budget — 20-40 min — and the only one that sends you to an external page.)

    Most of our workflows use Zotero (for managing references) and a small bridge program called an MCP server ("MCP" stands for Model Context Protocol — it's just the standard for letting Claude Code talk to outside services). Step-by-step instructions with screenshots-worth-of-detail are in install/mcp-add-zotero.md.

    Read that file in full and follow it before moving on. It covers:

    • Installing the Zotero desktop app
    • Generating a Zotero API key (with the exact UI labels)
    • Finding your numeric Zotero user ID
    • Installing uv (a Python package manager — needed because the MCP server is Python)
    • Installing the MCP server itself
    • Registering it with Claude Code
    • Testing it works

    When you are invited to a project's Zotero group library, you'll switch to it inside a Claude Code session. That part is also covered in the linked file.

    Step 4 — Clone this repo¶

    1. Make sure you have been invited to https://github.com/KaliGi/kai-team-claude. Check your email for the invitation, click the link, and accept.
    2. Pick a place on your computer to keep the repo. Anywhere works — common choices are ~/code/, ~/repositories/, or a dedicated Dropbox/github/ folder if you already keep cloned repos there. Cloning into a cloud-synced folder is fine for low-write repos like this one (where you mostly git pull rather than make many local commits); for very active development repos a non-synced folder is slightly safer.
    3. In the terminal, navigate to that location and clone: 
      git clone https://github.com/KaliGi/kai-team-claude.git
cd kai-team-claude
    4. If git asks for a username and password: the simplest beginner path is to install GitHub Desktop (https://desktop.github.com) and sign in once — git in the terminal then reuses its login and never asks again.
    5. Advanced alternative: a fine-grained Personal Access Token (not your GitHub password — GitHub disabled passwords for git over HTTPS in 2021). At https://github.com/settings/tokens?type=beta choose "Only select repositories" → kai-team-claude → Permissions → Contents: Read and write. When you paste it at the password prompt, nothing appears on screen — that's normal; press Enter.
    6. Or run gh auth login once (if you installed the GitHub CLI in Step 0).
    7. Confirm you're inside the cloned folder: 
      pwd
      The output should end in kai-team-claude. Stay in this folder for Step 5.

    Step 5 — Run the install script¶

    This copies the skills, agents, principles, templates, and docs from the repo into ~/.claude/ (the folder Claude Code reads from on your laptop). If you already have files there, the script backs them up first to ~/.claude/_backup_<timestamp>/ and then replaces them — nothing is lost.

    Note: slash commands (/academic, /review-paper, /bootstrap-project, /sync-bib, etc.) are NOT installed by this script. They come from plugins — see Step 6 below.

    Make sure your terminal is still in the kai-team-claude folder (Step 4.4 above).

    Windows (PowerShell): 

    powershell -ExecutionPolicy Bypass -File .\install\install.ps1
    - If PowerShell complains "scripts is disabled on this system", paste this exact line with the -ExecutionPolicy Bypass flag — it's the workaround. - The \ (backslash) in .\install\install.ps1 is correct on Windows.

    macOS / Linux: 

    bash install/install.sh

    You should see "Done." at the end. If anything went wrong, the script prints the error and exits — copy the error and open an issue on the repo (or ask whoever set you up).

    Step 6 — Register the marketplace, then install the plugins¶

    Slash commands ship via Claude Code's plugin marketplace. One-time install per laptop. These are built-in CLI commands — pasting them costs (almost) no tokens. Paste them exactly; don't describe to Claude what you want it to install:

    1. Close the terminal window completely, then open a fresh one.
    2. Type claude and press Enter, wait for the prompt.
    3. Register the marketplace first (without this, every install below fails with "marketplace not found"). Point it at the repo you cloned in Step 4: 
      /plugin marketplace add ~/kai-team-claude
      (Adjust the path if you cloned somewhere else. Alternative if you prefer pulling straight from GitHub: /plugin marketplace add KaliGi/kai-team-claude — requires your GitHub account to have access to the repo.)
    4. Install the plugins you need (each line is a separate command — type each, press Enter):
    Plugin Who needs it Install command
    project-workflow Everyone — project setup, bibliography, folder hygiene, git help /plugin install project-workflow@kai-team-claude
    academic-workflow Everyone writing or reviewing papers — drafting, review pipelines, references, data sources /plugin install academic-workflow@kai-team-claude
    r-research-workflow Anyone running R analyses — regressions, tables, figures, code review /plugin install r-research-workflow@kai-team-claude
    stata-research-workflow Anyone running Stata — replication scaffolds, esttab tables, code review /plugin install stata-research-workflow@kai-team-claude
    talks Only if you give research presentations /plugin install talks@kai-team-claude
    coord Optional, advanced: coordinate YOUR OWN multiple Claude sessions across projects. Never shares data between users. /plugin install coord@kai-team-claude
    1. Restart Claude Code one more time so the plugin registry reloads.

    Updating later: see the canonical 4-step ritual in the "Updating later" section below — don't improvise partial updates.

    Step 7 — Test it works¶

    1. Start Claude Code: claude
    2. Type /academic and press Enter — you should see the academic-writing orchestrator command load. Type /quit to exit.
    3. Try /bootstrap-project next — it should also load.

    If /academic or /bootstrap-project doesn't appear, check the plugin install:

    • Windows (PowerShell): Get-Content $env:USERPROFILE\.claude\settings.json | Select-String enabledPlugins -Context 0,10
    • macOS / Linux: grep -A 10 enabledPlugins ~/.claude/settings.json

    You should see project-workflow@kai-team-claude and academic-workflow@kai-team-claude in the list. If not, re-run Step 6.

    If you have stale bootstrap-project@kai-team-claude or research-pipeline@kai-team-claude entries (those plugins were merged into project-workflow in May 2026 and removed from the marketplace), uninstall them: 

    /plugin uninstall bootstrap-project@kai-team-claude
/plugin uninstall research-pipeline@kai-team-claude

    Read what you now have. After steps 5-7, your toolkit includes a dozen skills, several slash commands, and four principle docs. The one-page reference is at what-you-have-after-install.md — scan it once so you know what to reach for when.

    Step 8 — Get added to per-project resources¶

    This is per-project, not per-laptop. For each project, whoever runs it will invite you separately to:

    • A Dropbox folder (the project working directory — papers, code, data, working files)
    • A GitHub repository (the LaTeX source, bib file, and figures)
    • An Overleaf project (only if you'll edit there directly; many predocs skip this and let the Overleaf admin sync between GitHub and Overleaf — only the Overleaf project owner can set up that integration)
    • A Zotero group library (the project's shared references)

    Send whoever manages the project the addresses you used for each service so they can invite the right account.

    Updating later — THE canonical ritual¶

    This is the ONE place the update procedure is defined; other docs link here. The toolkit has two tiers, so updating has exactly four steps — the first two refresh the ~/.claude/ tier (skills, agents, principles), the third refreshes the plugin tier (slash commands), the fourth makes Claude Code reload both:

    1. Pull the repo. Terminal: 
      git -C ~/kai-team-claude pull
      (Adjust the path if you cloned elsewhere.)
    2. Re-run the install script. Terminal:
    3. Windows (PowerShell): powershell -ExecutionPolicy Bypass -File .\install\install.ps1
    4. macOS / Linux: bash install/install.sh
    5. Refresh the plugins. Inside Claude Code: 
      /plugin marketplace update kai-team-claude
    6. Restart Claude Code (close the session, start a new one).

    Why two tiers? The install script copies files into ~/.claude/ directly; plugins are managed by Claude Code's own registry — neither mechanism updates the other, so both steps are needed. If a plugin still looks stale after step 3, see Troubleshooting ("plugin seems stale").

    The install script uses per-item overlay — it replaces just the items the repo contains, leaves any personal items in ~/.claude/ alone, and backs up the previous version of each item it touches to ~/.claude/_backup_<timestamp>/.

    Want to preview what the install would change before running it? Run the audit script — it lists what's in your ~/.claude/ vs the repo without making changes:

    bash install/audit.sh

    It shows three groups: items in both (would be replaced), repo-only items (would be added), and local-only items (would be left alone). Safe to run anytime.

    Removing the toolkit¶

    Leaving the team or cleaning a machine:

    1. Inside Claude Code: /plugin uninstall <name>@kai-team-claude for each installed plugin (list them with /plugin).
    2. Remove the Zotero bridge if you added it: claude mcp remove zotero.
    3. Delete the items the install script placed in ~/.claude/ (skills/, agents/, principles/, templates/, docs/ — run bash install/audit.sh first to see exactly what's repo-managed vs yours; backups live in ~/.claude/_backup_<timestamp>/).
    4. Delete your clone of this repo, and revoke the Zotero API key + GitHub access token in the respective web UIs.

    Troubleshooting¶

    "command not found: claude" — Node.js install probably didn't add npm's global folder to your PATH. - Windows: close and reopen the terminal so it picks up the new PATH; if still broken, check that node --version works first. - macOS / Linux: run npm config get prefix to find where npm puts global packages (e.g., /usr/local). Then add export PATH="$(npm config get prefix)/bin:$PATH" to your shell profile (~/.zshrc on modern macOS, ~/.bashrc on Linux), close the terminal, reopen.

    "command not found: uvx" / "uv" — uv adds itself to PATH only in newly-opened terminals after install. Open a new terminal and try again.

    "npm install -g" fails with EACCES (macOS / Linux) — see Step 1.4 above.

    A plugin seems stale after /plugin marketplace update — the clean refresh is uninstall + reinstall: /plugin uninstall <name>@kai-team-claude then /plugin install <name>@kai-team-claude, then restart. (Only needed when the marketplace update didn't propagate; not part of the normal ritual.)

    /academic doesn't appear in Claude Code — the plugin isn't installed or enabled (slash commands ship via plugins, NOT via the install script). Inside Claude Code run /plugin, confirm academic-workflow@kai-team-claude is listed and enabled; if not, redo Step 6 (marketplace add, then install), then restart Claude Code.

    Skills fire but the principles file is missing — agents look up ~/.claude/principles/academic-writing.md. If that path doesn't exist on your machine, the install script didn't copy principles/ correctly. Re-run the install script.

    Zotero MCP errors out — the Zotero desktop app must be running for the MCP server to talk to it. Open Zotero and try again.

    git clone says "repository not found" — you have not been invited to the repository yet, or you accepted the invite with a different account. Ask whoever set up your access to (re-)invite the GitHub username you're cloning with.

    uv install on Windows blocked by IT policy — the irm | iex one-liner can be blocked. Download the installer manually from https://github.com/astral-sh/uv/releases and run the .msi file.

    Anything else — open an Issue on this repo (https://github.com/KaliGi/kai-team-claude/issues) or ask whoever set you up. Include the exact error text and what step you were on.
