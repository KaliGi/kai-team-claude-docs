    Where AI fits the paper — loops, gates, and the store¶

    The anatomy page named the hidden decisions every paper makes and rarely writes down, and laid out the arc: question, data, analysis, exhibits, argument, writing, review, submission. This page closes the circle: for each hidden decision, where it lives now, what produces it, and what keeps it from drifting when you cross the arc again.

    Everything here is built from one atom. A prompt is one instruction to one model call. One call gets one shot, and one shot is not how research gets made, so the toolkit wraps prompts in loops and hangs every loop off a shared set of documents. Three pieces have to exist before a redo set is computable: a place decisions live, a way work gets made against them, and a way to tell whether a check really ran. Store, loops, receipts, then the redo set they buy you, then one row per hidden decision.

    Decisions live in documents, not in memory¶

    The store is the set of project documents where your research decisions live between work sessions. Not anyone's memory, and not a chat window. We keep four documents per paper, one per hidden decision:

    • the glossary — each concept's canonical term, plus the alternatives you have banned;
    • the exhibit list — which exhibits exist and what each one shows;
    • the section plans — each paragraph's lead, and where each exhibit is cited;
    • the results numbers — the estimates the prose is allowed to quote.

    Why not the other two? Chat forgets: a new session starts blank, so a term you settled on Tuesday is invisible on Thursday. Memory misremembers: you recall renaming a concept, not which banned alternative you renamed it from. A document has neither problem, and a co-author or a script can read it too.

    Walk it with me. On the left is you, and the arrow leaving you is labelled approve: the only arrow that writes into the store. The middle box is the store with its four documents. Its outgoing arrow, read before any work starts, is concrete: a writing skill loads the section plan before drafting a word, a figure's labels get checked against the same glossary row the prose uses. On the right is the work; notice where its return arrow points, back to you rather than into the store. And notice what is missing: no arrow runs between kinds of work, so figure work never learns terminology from writing work. Both read the same glossary row, which designs the drift out rather than policing it.

    Work repeats until a check passes¶

    A loop repeats a piece of work until a check passes, never until it "looks done". That distinction carries the weight: "looks done" is a verdict issued by the thing being judged, and it is available on round one.

    You have met one loop already. The figure loop builds, renders, hunts for the legend sitting on a bar or the axis that says millions and means thousands, fixes, repeats once or twice, and only then shows you the result (self-correcting figures). Packaging makes it shippable rather than a personal habit: a skill is a saved, versioned prompt plus its scripts, so a co-author gets the identical loop. The fragile part is the exit condition. Inside a skill's instructions it is a soft rule Claude usually follows; as a gate it is a script with an exit code that fires whether or not anyone remembered it.

    Checks that leave receipts¶

    A receipt is a saved note that a check ran and passed, tied to the exact version of the thing it checked. Change the thing and the note visibly no longer applies. That is the feature, not a bug. Work it through on exhibit 3, an event-study plot, which carries the rest of this page:

    1. Monday. A separate agent reviews the figure with cold eyes, passes it, and writes a receipt: passed, figure version a4f9c2 — that last field a short fingerprint of the figure file's exact contents.
    2. Tuesday a co-author points out the event study identifies only off districts with a pre-period, so you rebuild exhibit 3 to cover those 27 rather than all
    3. The fingerprint is now 7c11e8, the receipt's a4f9c2 no longer matches, and the pass no longer counts. Nothing had to notice your edit.
    4. You re-run the review on 7c11e8. It passes and writes a receipt against 7c11e8, so exhibit 3 is checked against the figure that actually exists.

    Compare the honest human version, "I checked that figure last week." It was true when you said it and stays true after you rebuild, which is exactly the problem. A receipt makes "done" a property of a version, not of your recollection.

    Change one thing, redo only what depended on it¶

    When you change one thing, the redo set is the usually small set of other things that actually depended on it. Everything else stays done. (Its technical name is the stale set; I will say redo set from here.)

    Here is why writing hidden decisions down pays. "Paragraph 4.2 cites exhibit 3" is itself a research decision: real, load-bearing, normally unwritten. If it lives only in your head, Tuesday's rebuild leaves two options. Re-read all 41 pages, which nobody does in submission week. Or redo what you remember, which is cheap, wrong and silent, because the paragraph you forgot does not raise its hand. Write the link down and a third option appears: look it up.

    Run that arithmetic on the same rebuild. Across 41 pages and 6 sections the paper has 9 exhibits, 118 paragraphs with a recorded lead and a 22-slide deck: 149 tracked items.

    1. Exhibit 3's row in the exhibit list changes, because what it shows is now different. That is item 1.
    2. The section plans record which paragraphs cite which exhibit. Two of the 118 name exhibit 3, so both join. Running total 3.
    3. Exhibit 3's review receipt points at the old version of the figure, so by the rule above it stops applying. That is item 4, and the only one of the five that is not itself a tracked item.
    4. The deck records which exhibit each slide displays. Slide 14 shows exhibit 3, so it is flagged for a manual check rather than traced automatically. Item 5.
    5. Nothing else in the store names exhibit 3, so nothing else moves.

    Five items in all, four of them among the 149 tracked ones — that is under 3% of the paper. The other 116 paragraph leads, 8 exhibits and 21 slides stay done, and that is checkable rather than hopeful, because their own receipts still match.

    Two honest limits. The fan-out is not always one level deep: a number quoted in one of those two paragraphs and repeated later pulls that later paragraph in too. And the set is only as good as the links you recorded. I am confident about exhibit-to-paragraph links, which cost seconds to write while you are making the citation anyway, much less confident that a dependency nobody ever noticed is recoverable by any machinery. Better one item too big than one too small, and that is a preference, not a rule.

    The map — decision, document, loop, check¶

    One row per hidden decision from the anatomy page. Read each row left to right as a sentence: this decision lives here, is produced by this loop, and is guarded by this check.

    Hidden decision Where it lives in the store The loop that produces it The check that guards it
    What to call each concept The per-paper glossary: approved terms with their banned alternatives An agent proposes a term, you approve it, the approval is logged with a date, and only approved rows are ever enforced The glossary check scans the draft for the alternatives you banned and fails on a hit
    Which exhibits exist and what each shows The exhibit list, one line per exhibit Build, render, self-check, fix, then a separate agent reviews it with cold eyes The review receipt, tied to that exact version of the figure
    What each paragraph says, its lead The section plan, one lead per paragraph Leads first and you sign them off, then drafting: two drafters, a critic, a rewriter (writing tools) Each drafted paragraph is read back against the lead the plan recorded
    Where each exhibit is cited The placement column of that same section plan The same planning pass that settles the leads Every exhibit is cited where the plan says, and none is left uncited

    One of the four is a hard gate today. The glossary check runs as a script (check_glossary.py, documented here) with an exit code, so it cannot be talked out of failing. The other three are soft rules living as instructions in the skills, which Claude follows reliably but not inevitably: the figure loop runs its once-or-twice self-check because the skill says so, not because anything fires automatically. We promote a soft rule to a hard gate (how it works) when "usually" stops being good enough.

    Adopting one row rather than four? Make it the first. Terminology is cheapest to record, most visible when it drifts, and already has a page of its own.

    You make every decision¶

    None of this invents a research decision. An agent may propose a term, an exhibit or a lead, and a proposal has no force until you approve it. What the toolkit adds is memory and stubbornness: the store remembers the decision you made in March, the loops run until your check passes rather than until the output looks plausible, and the redo set hands you the honest list of what your change broke.
