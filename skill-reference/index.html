    Skill reference — what each skill does and when to use it¶

    A detailed entry per skill: what it produces, when to reach for it, an example prompt, and what it is not for. For the grouped quick view see the skills by family; for the flat invocation list with exact syntax see the full index.

    academic-workflow (plugin)¶

    bib-audit¶

    • What it does: catches hallucinated, chimeric, or broken references in a .bib via a dual-Claude audit -- two independent verification cascades run blind, then challenge each other on disagreements -- producing an evidence-backed scorecard.
    • When to use: before submission / circulation, or "check my bib for fake references", "verify citations", "did Claude hallucinate citations".
    • Example: "/bib-audit paper/references.bib"
    • Not for: refreshing or adding entries from Zotero (use /sync-bib, /add-cite-from-zotero).

    bootstrap-paper¶

    • What it does: scaffolds a new econ paper LaTeX project in Kai's house style -- paper.tex + appendix + preamble + labels (auto-FloatBarrier, appendix counters A1/A2, biblatex authoryear, threeparttable/dcolumn/tabularx) from the templates.
    • When to use: starting a new paper with no paper.tex yet -- "scaffold a new paper", "set up the LaTeX", "start a new paper in my style".
    • Example: "scaffold the paper LaTeX for this project, title "Roads and Revolt"
    • Not for: refactoring an existing paper (use /refactor-structure); slide decks (use the talks skill).

    build-data-source-table¶

    • What it does: emits a LaTeX data-sources appendix table from the datasets: block of replication_metadata.yaml (the YAML is the single source of truth; the table is regeneratable) -- caption + label + threeparttable, ready to \input into the appendix.
    • When to use: "build the data sources table", "data appendix table", after populating datasets: in the metadata.
    • Example: "build the data-sources appendix table from my replication metadata"
    • Not for: regression tables (use /build-fragment-table); projects with no populated metadata YAML (run /init-replication first).

    build-fragment-table¶

    • What it does: generates BOTH halves of a paper-ready regression table in Kai's outline-in-paper + fragment-from-code pattern (no stars; coef / [SE] / {p}; Mean-Control + N rows) -- the Stata esttab fragment block to paste in the .do, and the LaTeX outline to paste in the paper, with correct column counts.
    • When to use: "build me a fragment table", "wire this regression into the paper", "make a new house-style table".
    • Example: "build the fragment table + outline for the main treatment regression"
    • Not for: the data-sources appendix table (use /build-data-source-table); figures (use /coef-plot or real-data-figure).

    data-catalog¶

    • What it does: catalog + search + download for ~40 major empirical datasets (conflict, governance, economic, resources, climate, displacement, sanctions), with code templates (wbgapi / REST / direct file).
    • When to use: "what data exists for X", "find data on Y", "download dataset Z", "where can I get GDP / democracy / conflict / refugee data".
    • Example: "find and download V-Dem democracy scores for African countries"
    • Not for: plotting the data (use real-data-figure / map-figure); lecture data work (lecture pipeline owns that).

    humanize¶

    • What it does: read-only audit of .tex / .qmd / .md text for AI-voice tells -- boilerplate transitions ("Moreover", "It is important to note that"), AI-cliche lexicon ("delve", "tapestry"), em-dash overuse, symmetric paragraph shapes, tricolon abuse, hedging stacking. Produces a report; does NOT rewrite.
    • When to use: "humanize", "does this sound like AI", "de-AI this draft", "audit my prose for sycophancy", before journal submission. [Currently HALTED: auto-trigger disabled pending smoke-test.]
    • Example: "humanize the intro of paper/intro.tex"
    • Not for: actually rewriting (use kai-writing); structural writing critique (use scientific-writing-analysis).

    init-replication¶

    • What it does: scaffolds replication-package infrastructure into an EXISTING project -- replication_metadata.yaml + 00_setup scripts + paper/README placeholder -- with stubs auto-derived from project state (authors, dataset list, software language).
    • When to use: "make this project replication-ready", "set up the AEA replication scaffold", a paper that will need a replication package.
    • Example: "init the replication scaffold for this project"
    • Not for: fresh empty projects (use /bootstrap-project --replication-ready); projects that already have a populated metadata YAML (refuses without --force).

    lit-review¶

    • What it does: structured literature SEARCH + synthesis from the web -- thematic clustering, citation extraction, gap identification -- producing a written review with BibTeX-ready citations.
    • When to use: "find papers on X", "do a lit review", "what's the literature on...", "where's the gap in this field".
    • Example: "lit review on the resource curse and civil conflict"
    • Not for: processing an existing local literature/ PDF folder into a corpus (use /lit-corpus).

    preregister¶

    • What it does: drafts a structured preregistration document (OSF / AsPredicted / AEA RCT Registry style) from a research spec -- hypotheses, design, sampling plan, analysis plan, exclusions, inference criteria -- annotated with MUST/SHOULD/MAY clarity flags.
    • When to use: "preregister", "OSF preregistration", "AsPredicted", "AEA RCT registry", "preanalysis plan", before launching an experiment / data collection / analysis on unseen data. [Currently HALTED: auto-trigger disabled pending smoke-test.]
    • Example: "draft an AsPredicted preregistration for this RCT"
    • Not for: actual registry SUBMISSION (the user uploads to OSF/AsPredicted/AEA themselves).

    respond-to-referees¶

    • What it does: generates a structured response-to-referees document from a referee report and the revised manuscript -- maps each referee comment to the specific revision, classifies coverage (Addressed / Partially / Deferred / Disagreement), drafts polite-but-firm responses, runs CoVe post-flight verification on every "we added X on page Y" claim.
    • When to use: during R&R -- "draft response to referees", "map referee comments to revisions". [Currently HALTED: pending end-to-end test on a real referee report.]
    • Example: "draft response-to-referees from referee_report.pdf + revised_paper.tex"
    • Not for: drafting the revisions themselves (use kai-writing); deciding which comments to address (author's call).

    suggest-jel¶

    • What it does: suggests 3-5 JEL classification codes for a specific paper or grant proposal -- a primary block (2-3) + optional secondary, with close-alternative swaps and a paste-ready "JEL Classification:" line.
    • When to use: "suggest JEL codes for this paper", "what JEL codes should I use", or the paper.tex JEL placeholder.
    • Example: "suggest JEL codes for this abstract (paste the abstract)"
    • Not for: one-shot definition lookups ("what does D74 mean") -- those are answered inline.

    coord (plugin)¶

    coord¶

    • What it does: cross-session coordination -- check for and respond to messages between YOUR OWN Claude Code sessions running in different project folders (single user, many projects -- NOT team chat). Uses a private file-based channel with named threads.
    • When to use: "check coord", "any messages for me", "reply to that thread", "send a message to lp" (or any of your session shortnames), "what's in coord", "anything from lecture-pipeline".
    • Example: "/coord check"
    • Not for: team coordination across different users; bare "check inbox" (usually email).

    project-workflow (plugin)¶

    audit-exhibits¶

    • What it does: builds a fail-closed provenance manifest classifying every file under output/{figures,tables,maps,figures_external}/ as CODE-REPRODUCED (producing script exists), EXTERNAL (under figures_external/), MANUAL (paper-referenced but no producing code), or ORPHAN (not referenced anywhere). Writes data/documentation/exhibit_manifest.yaml.
    • When to use: pre-submission audit; "exhibit manifest", "which figures don't have producing code", "what would regenerate vs not", "/audit-exhibits". CI-ready: --strict exits non-zero on any ORPHAN.
    • Example: "/audit-exhibits --strict as a pre-submission gate"
    • Not for: numeric-claim auditing (use /audit-reproducibility); actually fixing the orphans (judgement call by the author).

    check-clone-discipline¶

    • What it does: session-level structural check for multi-clone projects -- confirms you're standing in YOUR clone (clone_/) and not at the shared container before any git operation, and surfaces container-hygiene issues + per-clone .data-in-parent marker presence.
    • When to use: at session start in any project with a "Multi-clone layout" CLAUDE.md block; "am I in the right clone", "is it safe to run git here", before the first git-write operation of a session.
    • Example: "check-clone-discipline at session start, before the first commit"
    • Not for: general git help (use git-assistant); single-clone projects (exits NOT_APPLICABLE).

    git-assistant¶

    • What it does: conversational git helper for economists who don't want to memorise commands. Translates "save this", "share with co-author", "back to main", "abandon this experiment" into the right git plumbing, runs it, translates errors into plain English, and re-runs 00_setup so output paths stay correct after branch switches.
    • When to use: any git action described in plain language -- save / commit / branch / push / pull / merge / sync / finalize / abandon / snapshot. Auto-triggers on those verbs when the object is the repo or a co-author's work.
    • Example: "save this and share with my co-author"
    • Not for: bib syncing (use /sync-bib); a throwaway experiment scratch script (use /experiment); paper-prose versioning in working/ (different convention).

    housekeeping¶

    • What it does: read-only 7-check audit of a project directory (plan/CHANGELOG drift, transient artefacts, doc-code path drift, orphan exhibits, wrong-folder pollution, untracked files, filename rot) producing a HIGH/MED/LOW severity Markdown report. Never modifies files.
    • When to use: "tidy up", "what's getting messy", "any orphan files", "anything to clean up", proactively after creating >5 new files in a session, or before opening a PR.
    • Example: "/housekeeping --all (report only) before a PR"
    • Not for: actually MOVING files (use /refactor-structure with confirmation).

    learn¶

    • What it does: appends a one-line correction or learned fact to the project's MEMORY.md (or your global ~/.claude/MEMORY.md with --global). Lightweight companion to /revise-claude-md (heavier synthesis) and /consolidate-memory (periodic prune).
    • When to use: any "remember that", "for next time", "from now on", "make a note", "we cluster at the village level" worth keeping.
    • Example: "/learn we cluster SEs at the village level for this paper"
    • Not for: large memory restructuring (use /consolidate-memory); deep CLAUDE.md edits (use /revise-claude-md).

    lit-corpus¶

    • What it does: converts a folder of academic PDFs into a token-efficient markdown corpus for lit review -- index.md (~400 tokens/paper: title, authors, year, abstract, JEL, keywords) + papers/*.md with cleaned full text. Incremental: only re-converts new or changed PDFs via SHA-256 hash tracking.
    • When to use: you have a folder of literature PDFs and want to query/synthesise them; after /sync-pdfs added new papers; "build my literature wiki", "convert my PDFs to markdown".
    • Example: "/lit-corpus literature/ literature/_wiki/"
    • Not for: one-off PDF queries (use pdf-query-recipe); searching the web for new papers (use /lit-review).

    overleaf-sync¶

    • What it does: diagnoses Overleaf<->GitHub sync conflicts (typically post-restructure stale-snapshot branches from the Overleaf git bridge), classifies each (stale snapshot / real edits / mixed), and recommends the right resolution -- often git merge -s ours <overleaf-branch>. Never auto-merges; you approve.
    • When to use: "overleaf conflict", "overleaf is fighting me", "manual merge from overleaf"; auto-suggests when the project is Overleaf-mastered AND an overleaf* branch is present.
    • Example: "/overleaf-sync --branch overleaf-bridge"
    • Not for: general git conflict resolution (use git-assistant or /resolve-conflict).

    sync-codebook¶

    • What it does: two-codebook synchronisation (survey-frozen + derived-live) for survey + analysis projects. Identifies derived variables (set-difference between the analysis .dta and the survey codebook), merges with hand-authored YAML descriptions, emits the derived codebook markdown. --strict exits non-zero on any TODO -- CI-ready.
    • When to use: "sync codebook", "update derived codebook", "what variables don't have descriptions yet", "audit codebook", or any project with both a frozen survey codebook and derived variables.
    • Example: "/sync-codebook --strict before submission"
    • Not for: bib syncing (use /sync-bib); PDF syncing (use /sync-pdfs); fresh-data-source codebook scaffolding (use /init-replication first).

    r-research-workflow (plugin)¶

    audit-reproducibility¶

    • What it does: cross-checks the numeric claims in a manuscript (point estimates, SEs, p-values, counts) against the actual R/Stata/Python outputs and reports PASS/FAIL per claim against tolerance thresholds.
    • When to use: a pre-submission / pre-replication-release check -- "audit the paper", "verify the paper matches the code", "reproducibility audit".
    • Example: "audit paper/paper.tex against output/tables/ and data/processed/"
    • Not for: producing or reviewing the analysis code (use /data-analysis / /review-r); checking exhibit provenance/orphans (use /audit-exhibits).

    coef-plot¶

    • What it does: ONE coefficient figure from a saved regression fit (.rds) or a fresh estimation -- forest plot, event-study plot, or multi-spec comparison panel -- in the research house style, saved to output/figures/.
    • When to use: "coefplot for the main regression", "forest plot of these estimates", "event-study plot", "plot the coefficients from this .rds".
    • Example: "event-study plot from data/processed/did_fit.rds"
    • Not for: raw-data scatter / time series (use real-data-figure); choropleths (use map-figure); lecture/slide figures.

    data-analysis¶

    • What it does: the FULL-PIPELINE umbrella for R analysis -- exploration -> cleaning -> regression -> publication-ready tables & figures -- appending to the canonical 01_cleaning.R / 02_analysis.R (one-canonical-script rule), with outputs branch-redirected on a non-main branch.
    • When to use: a FRESH dataset where you want the end-to-end flow -- "analyze this dataset", "explore this CSV and run the main spec", or you point at a new .csv/.dta without naming a single phase.
    • Example: "analyze this panel.dta end to end -- summary stats, main spec, and the key figure"
    • Not for: a single phase (use /descriptives, /regression, or /coef-plot); reviewing an existing script (use /review-r); lecture figures.

    descriptives¶

    • What it does: publication-ready descriptive statistics for research data -- summary-stats tables, treatment-vs-control balance tables, distribution diagnostics, missingness reports -- written to output/tables/ (.tex) and output/figures/diagnostics/.
    • When to use: you need "Table 1" / summary stats / a balance check on one dataset without a full pipeline -- "give me a balance table", "summary stats on X", "describe Y by treatment group".
    • Example: "balance table of pre-treatment covariates by treatment group"
    • Not for: a full analysis (use /data-analysis); lecture figures (lecture-pipeline data-visualizer).

    regression¶

    • What it does: estimate ONE regression specification (or a small column-stack of related specs) -- OLS / FE / IV / DID via fixest -- and emit the fitted model, tidy results, a publication-ready .tex table, and post-estimation diagnostics.
    • When to use: you want a specific spec run, not a whole pipeline -- "regress Y on X with state FE, cluster at state", "IV with z", "the DID spec".
    • Example: "regress wage on schooling with year + state FE, clustered at state"
    • Not for: a coefficient PLOT (use /coef-plot); the full exploration-to-figures pipeline (use /data-analysis); lecture figures.

    review-r¶

    • What it does: reviews EXISTING R scripts on disk via the r-reviewer agent (11 categories: structure, reproducibility, functions, domain correctness, figures, numerical discipline, ...) and writes a report. Does NOT write new scripts.
    • When to use: "review my R script", "audit code/03_main.R", "what's wrong with this script", or before committing any .R you just changed.
    • Example: "review code/02_analysis.R before I commit"
    • Not for: PRODUCING new analysis (use /data-analysis, or the atomic /descriptives / /regression / /coef-plot).

    stata-research-workflow (plugin)¶

    review-stata¶

    • What it does: reviews EXISTING Stata .do files on disk via the stata-reviewer agent (12 categories: structure, header, reproducibility, programs, domain correctness, esttab tables, graph export, comments, error handling, polish, AEA compliance) and writes a report. Does NOT write new scripts.
    • When to use: "review my Stata script", "audit code/03_main.do", "what's wrong with this do-file", or before committing a .do you changed.
    • Example: "review code/02_analysis.do before I commit"
    • Not for: PRODUCING new Stata pipelines (use /stata-replication).

    stata-replication¶

    • What it does: end-to-end Stata RESEARCH pipeline -- scaffolds the canonical 00_setup / 01_cleaning / 02_analysis.do triad, runs them via stata-mcp, logs to output/logs/, and emits esttab tables + graph PDFs to $tables/$figures. The Stata counterpart to /data-analysis.
    • When to use: the project's analysis language is Stata -- "set up the Stata pipeline", "scaffold the .do files", "AEA replication package in Stata".
    • Example: "scaffold and run the Stata pipeline for this .dta"
    • Not for: R projects (use /data-analysis); reviewing existing do-files (use /review-stata).

    talks (plugin)¶

    research-presentation¶

    • What it does: design and draft academic research presentations -- conference talks (15-20 min), department seminars (60-90 min), job market talks (JMP), brown-bags, workshop talks. Covers architecture-by-length (the Sargent rule -- prepare for 2/3 of your slot), intro design (Keith Head's Big 5, ABT, the Hourglass), identification defence, slide rhetoric, the Squint Test for charts.
    • When to use: "create a talk", "design my presentation", "structure my seminar", "outline my JMP", named formats (NBER, AEA session, JMP, departmental seminar). Use even when the user doesn't name the skill -- if they're making slides for presenting a paper, this is the right one.
    • Example: "design my 90-minute job market talk"
    • Not for: teaching lectures with exercises/quizzes (use create-lecture); a single data figure (use real-data-figure); a single TikZ/DAG diagram (use tikz-figure); pre-ship critique (use adversarial-review).

    Top-level skills¶

    adversarial-review¶

    • What it does: structures a hostile pre-ship review of any artefact (code, figure, paper draft, slide deck, data analysis, design doc, build plan) where the reviewer is EXPLICITLY tasked to find flaws, not confirm correctness. Output is a HALT/HIGH/MEDIUM/LOW/NIT findings list, not a cheerleading summary.
    • When to use: "critical review", "red-team", "devil's advocate", "poke holes in X", "what could go wrong here", "sanity check before I ship", "find weaknesses", "stress-test", any time the user wants honest weakness-finding rather than rubber-stamp approval.
    • Example: "adversarial review this design doc before I share it"
    • Not for: a paper for a journal (use /review-paper / /review-paper-light); a grant proposal (use /review-grant); writing-quality critique (use scientific-writing-analysis); producing or revising text (use kai-writing).

    kai-writing¶

    • What it does: personalised academic-prose pipeline for Kai's voice -- two competitive drafters + a critic + a rewriter run internally before you see any output. Produces revised drafts of contribution paragraphs, intros, conclusions, abstracts, definitions, referee responses, etc.
    • When to use: any "write", "draft", "revise", "polish", "rewrite this in my style" request for academic prose.
    • Example: "write the contribution paragraph for this paper, two drafters then critic"
    • Not for: writing-quality DIAGNOSIS without rewriting (use scientific-writing-analysis); a journal-grade referee report (use /review-paper); slide design (use research-presentation).

    map-figure¶

    • What it does: publication-quality choropleth & country-level maps from real data in R (sf + ggplot2), with the map-specific traps handled -- name/ISO reconciliation + a loud anti-join, equal-area projection, skew-aware binning, rates-not-counts, and an explicit no-data key.
    • When to use: a research / working-paper / policy-brief map where the geography IS the unit -- "make a map", "choropleth", "map X by country", "shade countries by X".
    • Example: "choropleth of battle deaths per capita by country, 2018-2024"
    • Not for: lecture / slide maps (the lecture-pipeline data-visualizer owns those); non-map charts like time series or scatter (use real-data-figure).

    qualitative-survey-coding¶

    • What it does: turns open-ended survey responses into validated, paper-ready quantitative variables using an LLM as the coder with human validation. Handles codebook design, hard-code vs free-code decisions, inter-coder agreement, and the audit trail.
    • When to use: "code these open-ended answers", "classify free-text survey responses", "turn this text into a measure", "design a codebook for open-ended", any qualitative-to-quantitative conversion of survey text.
    • Example: "code these 800 free-text answers about trust in government into a 3-level scale"
    • Not for: quantitative survey processing (use /descriptives or /regression); a literature corpus (use /lit-corpus).

    real-data-figure¶

    • What it does: publication-quality figures from REAL data -- time series, scatter, coefficient, lollipop -- sourced from OWID, World Bank, V-Dem, UCDP, ACLED and others, cleaned and plotted in the research house style with honest self-scoring.
    • When to use: any figure whose value depends on real numbers being correct, or when you name a source (OWID / World Bank / V-Dem / UCDP / ACLED) -- "plot GDP for these countries", "chart the democracy index over time".
    • Example: "plot GDP per capita for England vs France, 1600-1800, from Maddison"
    • Not for: maps shaded by country (use map-figure); coefficient plots from a SAVED model fit .rds (use /coef-plot); schematic / conceptual diagrams (use tikz-figure); pure data download with no plot (use data-catalog).

    scientific-writing-analysis¶

    • What it does: analyses scientific manuscripts for writing quality using Jean-Luc Lebrun's "Scientific Writing" (2007) framework augmented with econ-specific conventions (Cochrane, McCloskey, Nikolov). Diagnoses paragraph progression, lead sentences, flow, structure -- HOW the prose works, not what it claims.
    • When to use: "analyze the writing quality", "Lebrun review", "diagnose this draft's structure", "what's wrong with the flow".
    • Example: "scientific-writing-analysis of the intro and the contribution section"
    • Not for: actually rewriting (use kai-writing); checking factual / argumentative content (use /review-paper or adversarial-review); AI-voice tells specifically (use humanize).

    simulation-figure¶

    • What it does: builds Monte Carlo simulations + interactive parameter explorations that show how econometric methods break under assumption violations -- weak IV, parallel-trends, staggered DID, TWFE bias, exclusion-restriction failure. Produces BOTH a static multi-panel PDF (for Beamer/print) AND an interactive Plotly HTML with animation slider (for RevealJS/browser).
    • When to use: "simulate", "Monte Carlo", "show what happens when the instrument is weak", "demonstrate IV bias", "stress test the identification", "when does this method fail" for a talk, lecture, or appendix.
    • Example: "simulate weak-IV bias as the first stage F drops from 30 to 5"
    • Not for: real-data plots (use real-data-figure); a single conceptual diagram (use tikz-figure); a lecture map (lecture-pipeline data-visualizer).

    tikz-figure¶

    • What it does: builds, tests, and debugs publication-quality TikZ figures -- mechanism diagrams, DAGs for causal identification, game trees, decision trees, flowcharts, schematic maps, schematic time series. Uses the Cunningham "standalone-test" pattern so compile errors are crystal-clear.
    • When to use: "make a DAG", "mechanism diagram", "causal diagram", "game tree", "decision tree", "flow chart" in LaTeX/Beamer/Quarto; also when diagnosing a failed TikZ compile ("undefined key", "missing $", "you need \usetikzlibrary{...}").
    • Example: "build a DAG for the IV identification of X -> Y with Z"
    • Not for: real-data figures (use real-data-figure); choropleths (use map-figure); Monte Carlo simulations (use simulation-figure).
