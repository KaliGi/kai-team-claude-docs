    Detailed setup walkthrough¶

    Why this page. The one-time account-and-folder setup is the only genuinely fiddly part of the whole system — get it right once and the daily work is easy. So it's worth doing slowly and in order, which is what this walkthrough is for.

    A picture-by-picture walkthrough for getting onto a shared paper from a standing start — no command-line experience assumed. If you already have Dropbox and GitHub working, skip to the 15-minute quickstart.

    (Screenshots are being added — the written steps already tell you exactly what to do.)

    Before you start¶

    You need accounts for Dropbox, GitHub, and Claude Code (a paid Claude plan — the free tier won't get you far). Whoever set up the project sends you two invitations — one to the Dropbox folder, one to the GitHub repository. Accept both before step 1.

    Step 1 — Install Dropbox and accept the shared folder¶

    Install Dropbox from dropbox.com/install and sign in. When you accept the Dropbox folder invitation, the project appears under your Dropbox automatically — you do not download anything by hand.

    Screenshot coming

    Will show: Dropbox tray icon showing the shared project folder synced (green tick)

    What to check: wait until the Dropbox icon shows a green tick — that means the project (code and the heavy data) has finished downloading to your laptop.

    Step 2 — Find the folder on your computer¶

    The project lives at C:\Users\<you>\Dropbox\<project-name>\ (Windows) or ~/Dropbox/<project-name>/ (Mac). Open it once in your file browser so you know where it is — you'll point Claude Code at it next.

    Screenshot coming

    Will show: File browser open at the project folder, showing code / paper / data subfolders

    Step 3 — Install Claude Code and sign in¶

    Install Claude Code (desktop app from claude.com, or the CLI) and sign in with your Claude subscription. This is a one-time step per computer.

    Screenshot coming

    Will show: Claude Code desktop app after sign-in

    Step 4 — Connect GitHub (once)¶

    Accept the GitHub repository invitation (it arrives by email). Then open Claude Code inside the project folder from step 2 and type:

    "Help me sign in to GitHub so I can push and pull."

    Claude walks you through it — usually installing GitHub Desktop and signing in once, which quietly handles authentication from then on.

    Screenshot coming

    Will show: GitHub Desktop signed in

    Step 5 — Tell Claude who you are (once)¶

    So your name is stamped on your work, type into Claude Code:

    "Set my git name to 'Your Name' and email to you@university.edu."

    Step 6 — Overleaf (only if your project uses it)¶

    Most setups don't need this — skip it unless your team wants track changes. Everything compiles locally (latexmk -pdf paper.tex); Overleaf's one real draw is track changes for marking up prose in the browser. So:

    • You're a co-author joining an Overleaf-mastered project: you don't set anything up — accept the Overleaf invitation, write/track-change prose in the browser, and clone the GitHub repo into your folder as in the steps above.
    • You're the project owner choosing to use Overleaf: you do this once, and it's worth doing first — link the Overleaf project to the GitHub repo via Overleaf's Menu → Sync → GitHub/Git (a paid-plan feature). Full step-by-step + the owner-first rationale: new to Overleaf?.
    • Not using Overleaf: nothing to do — compile locally and carry on.

    That's the entire setup. From here on, you just talk to Claude Code — see the 15-minute quickstart for the everyday "say this to do that" table.
