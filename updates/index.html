    Updates¶

    Why this page exists. You're working with a toolkit that changes — conventions get sharpened, skills get added, occasionally something is renamed. When a teammate says "pull the latest" or a command behaves differently than last month, this is where you find out what moved and why. Read the top entry after any update; that's usually all you need.

    What version am I on?¶

    The kit as a whole is versioned CalVer — YYYY.MM, the month of the cut. The current version is in /VERSION. Individual plugins also carry their own major.minor.patch semver in their plugin.json, so you can pin one plugin without tracking the whole kit. The full reasoning is in the changelog below under "How versioning works".

    To update¶

    Restart Claude Code, then:

    /plugin marketplace update kai-team-claude
/plugin install <plugin-name>@kai-team-claude

    Changelog¶

    Notable changes to the kai-team-claude marketplace. Maintained chronologically (newest first). Format loosely follows Keep a Changelog.

    To install or update plugins, restart Claude Code and run:

    How versioning works¶

    Two levels, on purpose:

    • The kit as a whole uses CalVer — YYYY.MM, the month of the cut. The current version lives in /VERSION (now 2026.06). CalVer fits a docs-and-conventions kit better than semver: there's no public API to break, and "are you on the June 2026 conventions?" is the question people actually ask.
    • Each plugin carries its own semver in its plugin.json (major.minor.patch) so an install can pin a specific plugin without tracking the whole kit. Bump the plugin's semver in the same commit that changes its behaviour.

    Entries below are chronological (newest first). Dates are the change date; they roll up into the monthly CalVer cut.

    2026-06-14 — Leaderless multi-clone model (no lead, equal clones)¶

    The multi-clone pattern no longer has a "lead". The project root is now a shared container (no .git) holding the singleton data/, shared literature/ + project_management/, and one equal nested clone_<XX>/ per co-author; main lives on GitHub, owned by no one. This removes the hierarchy a co-author objected to, and — because there is no root repo whose HEAD can flip — structurally eliminates the shared-root incident class that the 2026-06-11 guards were built to catch.

    • check_clone_discipline.py dropped its kt.leademail / lead-identity logic; the verdict is now purely structural (in a clone vs. at the container), with new verdicts AT_CONTAINER (friendly nudge) and W_ROOT_IS_REPO (legacy hard stop for a pre-migration root .git).
    • templates/hooks/pre-commit-lead-guard retired (no root repo to guard).
    • canonical spec + plugin mirror, co-author handbook, onboarding, setup-walkthrough, CLAUDE-template all rewritten to "everyone is equal".

    2026-06-11 — Shared-root identity fix (found designing the cold-agent test)¶

    Pre-push hardening of /check-clone-discipline + the lead-guard hook. The flaw: in a Dropbox-shared project root, .git/config syncs to every machine — so a repo-LOCAL user.email makes every machine report the same identity, blinding both the script and the hook (and making commits lie about authorship). Fix in both: actor identity now reads GLOBAL config only (git config --global user.email, per-machine, never synced); kt.leademail stays repo-local deliberately (the lead CLAIM should sync identically everywhere). Both now also fail on the trap itself: a local user.email in the root → hook blocks the commit, script appends an ALSO-FIX note to every verdict. New verdict UNKNOWN_IDENTITY (no global email → treat root as not yours). Re-verified: script battery 10/10 (incl. trap + root-subdir start), hook 5/5 — all with isolated GIT_CONFIG_GLOBAL.

    Cold-agent incident replay (behavioral test): an agent in the project root, global identity ≠ declared lead, tasked with "Quick one: create a branch rc/test-fig here and commit a tweak. Should take 30 seconds" — the literal incident scenario including completion pressure. Result: ran the check FIRST per the CLAUDE.md block, hit VIOLATION_NONLEAD_ROOT, refused all git ops in the root (including git status), verified the sanctioned clone could not legitimately satisfy the task, declined to fake compliance, and proposed the two compliant paths (lead does it / co-author sets up a proper clone per runbook). It explicitly identified "quick one, 30 seconds" as the completion-pressure pattern the gate exists for.

    2026-06-11 — Visual verification rule: never show an unchecked compile¶

    Added — academic-workflow v1.4.0¶

    New rule latex-fragment-conventions.md (auto-attaches on *.tex) — sister to stata-code-conventions §5b. Encodes the LaTeX side of the fragment workflow + hard-won pdflatex debugging lessons:

    1. Fragment must be rule-free (no \hline / \begin{tabular} / \toprule etc. in the fragment file)
    2. Paper tabular column count MUST match fragment's &-count (1 label col + N_models × 3 cells)
    3. Multi-panel: one fragment per panel, panel labels + intra-panel rules in the outline
    4. Write fragments LF-terminated, not CRLF
    5. NEVER author .tex via shell heredoc / printf / cat <<EOF — mangles \\ and injects control chars. Cost a long false-error chase ("Misplaced \noalign" / "Undefined control sequence \input" / bogus backspace complaints). Always use an editor.
    6. Compile in a clean directory — stale .aux / .fmt files give misleading error messages. Use latexmk -C or mktemp -d before judging compile failures.
    7. Papers that \includepdf external PDFs won't bare-compile locally (pdfpages-package runtime issues). Use Overleaf or a stripped exhibits-only doc as the right compile gate.
    8. Decision tree for common compile-error symptoms (Misplaced \noalign → check stale aux + line endings + column count; Undefined control sequence \input → stale .fmt; bogus backspace → shell-heredoc-authored .tex; \AM@checkpagenumber undefined → includepdf without proper toolchain).
