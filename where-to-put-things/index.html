    Where to put things¶

    A quick lookup. For the why, examples, and anti-patterns per topic, follow the link in the right-hand column.

    The full canonical layout lives in project-structure; this page is the answer to "I have this thing — where does it go?".

    Most topic groups have a dedicated page for the why, examples, and anti-patterns: data-provenance, notes-and-feedback, submissions, literature, experimental-organization, grants, and the full folder layout (which covers the IRB, admin, and presentations conventions). Each table below is the quick lookup; the linked page is the deep dive.

    Data¶

    Artefact Canonical home
    Raw data data/raw/ (flat, named clearly)
    Processed data data/processed/ (built by code/01_clean.{R,do,py} — any language, not just .do)
    Codebooks data/documentation/ (paired by name with raw)
    Source notes data/raw/SOURCES.md

    Deep dive: data-provenance.

    Notes and feedback¶

    Artefact Canonical home
    Meeting notes project_management/notes_and_feedback/
    Co-author comments / feedback project_management/notes_and_feedback/
    Internal discussion transcripts project_management/notes_and_feedback/

    Deep dive: notes-and-feedback.

    Submissions and revisions¶

    Artefact Canonical home
    Submitted paper PDF (per round) project_management/submissions/<NN_journal>/
    Cover letter PDF project_management/submissions/<NN_journal>/
    Cover letter TeX (editable) project_management/submissions/<NN_journal>/overleaf/ (Overleaf-synced)
    Response-to-referees PDF project_management/submissions/<NN_journal>/
    Referee reports — as received (PDF / txt from the journal) project_management/submissions/<NN_journal>/ (the historical record of the round)
    Submission log (one-liner per round) project_management/submission_log.md
    Response-to-referees TeX + agent-formatted referee reports TeX paper/revisions/<JOURNAL>/ (parallel to paper/presentations/; named by JOURNAL — e.g. paper/revisions/RESTAT/, paper/revisions/QJE/ — so co-authors get the response in their Overleaf project and can edit with track changes)

    Deep dive: submissions.

    Literature¶

    Artefact Canonical home
    Literature PDFs literature/<citekey>.pdf (via /sync-pdfs from Zotero)
    Literature MD corpus literature/_wiki/ (via /lit-corpus)

    Deep dive: literature.

    Experimental organization¶

    Artefact Canonical home
    Pre-registration project_management/experiments/<NN>/
    IRB approval (experiment-specific) project_management/experiments/<NN>/
    Randomization script project_management/experiments/<NN>/
    Pilot memos (what we learned) project_management/experiments/<NN>/
    Pilot data data/raw/pilot_<…>.csv (canonical flow — cleaned by 01_clean like main data) — or project_management/experiments/<NN>/pilot_data/ if it stays internal only
    Randomization assignment file data/documentation/ (it documents the experimental design realisation, not raw observation)

    Deep dive: experimental-organization.

    IRB and institutional paperwork¶

    Artefact Canonical home
    IRB approval (project-level / institutional master letter) project_management/IRB/
    Ethics committee correspondence, amendment filings, expiration extensions project_management/IRB/
    Funding award letter / grant administrative correspondence (for the funded grant — proposal for a new grant goes in its own folder, see Grants) project_management/admin/
    Co-author contracts, NDAs, data-sharing agreements project_management/admin/
    Conference / workshop acceptance letters, formal travel reimbursements project_management/admin/

    Deep dive: folder structure §2a/§2b.

    Grants¶

    Artefact Canonical home
    Grant proposal (writeup, references.bib, output, presentations, internal feedback) Own folder outside any research project: grant_<funder>_<NN>/

    Deep dive: grants.

    Presentations¶

    Artefact Canonical home
    Conference / seminar slides + their assets (logos, photos) paper/presentations/<venue>_<date>/ — assets live in the same folder as the deck so it compiles cleanly

    Deep dive: folder structure §5 (the presentations sub-pattern; the canonical layout doc covers the top-level convention).

    Covered elsewhere¶

    For code-side scratch and throwaway-script questions, see coding-workflow:

    • .claude/tmp/ — Claude session scratch (gitignored; inside your clone at clone_<XX>/.claude/tmp/ in multi-clone projects, not at the container root)
    • code/_exploratory/ — throwaway experiment scripts via /experiment (merged back into 02_analysis or deleted; not retained in main)
    • The branch-aware output/_exploratory/<branch>/ redirect for feature-branch outputs

    What's on each topic page¶

    • notes-and-feedback — meeting notes, co-author feedback, reviewer reports, internal discussion transcripts. Where the team's institutional memory accumulates.
    • submissions — per-round submission materials: cover letters, response-to-referees, submitted PDFs. Why gitignored, naming convention, the link to the submission log.
    • literature — the Zotero → literature/ → markdown-wiki pipeline. Why we recommend a markdown version of every paper (LLM efficiency).
    • experimental-organization — the split: planning in project_management/experiments/, collected data in data/raw/ + data/documentation/. Why every experimental dataset needs a codebook before data collection.
    • grants — separate folder convention for grant proposals; light-touch recommended layout.
    • full folder layout — the deep reference behind this cheat sheet: project_management/ internals (IRB, admin), multi-paper projects, the grants and presentations sub-patterns, with a worked project tree.
