    Common tasks, step by step¶

    The INDEX tells you what each tool does; this page tells you which tools to chain for a real task, with prompts you can paste verbatim. Six recipes cover ~80% of team usage.

    How to read a recipe: the goal → why this chain → the steps with exact prompts. Prompts in code blocks are pasteable as-is into a Claude Code session opened in the project folder (adjust names in <angle brackets>).

    Drift guard: scripts/release_check.sh verifies every command and skill named on this page still exists. If you rename a tool, this page fails the check until updated.

    1. Start a new project (day 1)¶

    Why this order: the project scaffold must exist before the paper scaffold (the paper lands inside it), and the replication metadata is cheapest to set up while the project is still empty — retrofitting it later is the painful version.

    1. Open Claude Code in the new (or messy existing) project folder. 
      /bootstrap-project
      Interactive: asks project mode, collaborators, Zotero setup, code stack; scaffolds the canonical folders + CLAUDE.md + .gitignore.
    2. If the project will have a LaTeX paper in git: 
      Scaffold the paper skeleton with /bootstrap-paper — title "<working title>", authors <names>.
    3. Wire the replication package early: 
      Run init-replication to set up the replication metadata.

    Result: canonical folders, CLAUDE.md, paper skeleton, replication metadata — every later recipe assumes this baseline exists.

    2. Add a figure to the paper¶

    Why this chain: work happens on a branch so main always compiles; the figure skill picks the right data source and styling; the explicit copy step is what moves a finished exhibit into the PR (nothing happens "automatically on merge"). Full git mechanics: handbook §2.6.

    1. Branch first (in your clone, multi-clone projects): 
      Make a branch for the new conflict-trends figure.
    2. Build the figure — pick by type:
    3. Real-world data (World Bank, UCDP, V-Dem, OWID…): 
      Plot battle-related deaths in Sub-Saharan Africa 1990-2024 from UCDP, OWID style, save as conflict_trends_v1.
      (fires real-data-figure)
    4. Mechanism diagram / DAG / game tree: ask for a TikZ diagram (fires tikz-figure)
    5. Coefficient/event-study plot from a saved fit: /coef-plot
    6. Method-breakdown simulation: ask to "simulate what happens when the instrument is weak" (fires simulation-figure)
    7. The script writes to output/_exploratory/<your-branch>/figures/. When final, promote it — copy to canonical output/figures/ and commit script + exhibit + paper reference together (handbook §2.6 step 6 has the exact commands).
    8. Before the PR, check exhibit provenance: 
      /audit-exhibits
    9. Push the branch, open the PR.

    3. Build or refresh the regression tables¶

    Why this chain: the fragment pattern (table numbers produced by code, table skeleton living in the paper) is the house style — it keeps the AEA replication mapping clean and stops hand-edited numbers from drifting from the code. The least discoverable high-value tool in the toolkit.

    1. For each table: 
      /build-fragment-table — outcomes: <y1, y2>, treatment: <D>, FE: <unit, time>, cluster: <unit>. Print to chat first.
      Emits BOTH the Stata esttab block and the matching LaTeX outline with correct column counts.
    2. Data-sources appendix table (reads the replication metadata from recipe 1): 
      /build-data-source-table
    3. Survey/analysis projects with the two-codebook split — refresh the derived codebook after the pipeline ran: 
      /sync-codebook

    4. The pre-submission gauntlet¶

    Why this order: cheap checks first. The light review takes a minute and catches contribution/identification problems that would make the 30-minute full review a waste; the mechanical audits run last because they check the final text against the final numbers.

    1. One-minute pre-screen: 
      /review-paper-light
      Fix anything major it flags before proceeding.
    2. The full 6-agent referee report: 
      /review-paper <target journal>
    3. References are real and well-formed: 
      Run bib-audit on paper/references.bib.
    4. Every number in the text matches the code outputs: 
      Run audit-reproducibility against the manuscript.
    5. JEL codes for the title page: 
      /suggest-jel

    (After an R&R: respond-to-referees exists but is HALTED pending its first real-world test — see working/TODO.md.)

    5. Add a citation¶

    Why three paths: not everyone has Zotero, and nobody should be blocked on bibliography plumbing. Full workflow: docs/co-author-onboarding.md.

    • No Zotero (anyone): type \citep{authorYEARkeyword} in the .tex, never touch references.bib — the key surfaces as a "pending orphan" for someone with Zotero to source.
    • One-off pull from Zotero: 
      /add-cite-from-zotero <citekey or title fragment>
    • Full refresh (read-only against Zotero, anyone can run): 
      /sync-bib

    6. Which writing tool, when¶

    Why this matters: four tools legitimately claim "review my text" and they do different things. Pick by what you want back:

    flowchart TD
    Q["I have text. What do I want back?"] --> P["New or rewritten PROSE<br/>in Kai's voice"]
    Q --> DIAG["A DIAGNOSIS of the<br/>writing quality"]
    Q --> ORCH["Many things at once<br/>across a chapter/paper"]
    Q --> FLAW["Someone to attack it<br/>before I ship"]
    P --> P2["kai-writing (auto)"]
    DIAG --> D2["scientific-writing-analysis (auto)"]
    ORCH --> O2["/academic"]
    FLAW --> F2["adversarial-review (auto)"]
    You want… Use Paste
    Text PRODUCED or REVISED in Kai's voice (intro paragraph, abstract, referee response prose) kai-writing skill Draft the contribution paragraph in Kai's style: <bullet points>
    A DIAGNOSIS of the writing (Lebrun codebook: progression, clarity, reader energy) — no rewriting scientific-writing-analysis Run a Lebrun analysis on the introduction.
    A multi-agent ORCHESTRATION across a whole chapter/paper (review + polish + figures + bib in parallel) /academic /academic review chapter 3
    Hostile flaw-finding before you ship anything adversarial-review skill Red-team this draft before I send it.

    (An AI-voice audit skill, humanize, exists but is currently HALTED — see working/TODO.md.)
