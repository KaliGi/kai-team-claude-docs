    The skills, by family¶

    This is the by-purpose view of the toolkit: skills grouped by what you'd reach for them to do, each one expandable for when and how to use it. It's the counterpart to the full list of commands & skills (the exhaustive flat catalogue with exact invocation) — start here to find the right tool, go there for the complete reference.

    How to read this: each entry is collapsed — click it to see when to use it and how to fire it. Most skills auto-trigger on matching language; anything with a /name you can also type explicitly (see Triggering skills). Install is per plugin — see Install the toolkit.

    Writing & editing¶

    kai-writing — drafts and revises academic prose in your voice

    For writing or polishing any paper prose — contribution paragraphs, intros, abstracts, referee responses. Runs two drafters → critic → rewriter internally, so you see a revised draft, not a first pass. Fire it: ask "write/revise this in my style," or it auto-triggers on prose tasks.

    scientific-writing-analysis — diagnoses writing quality (Lebrun framework)

    For a structured critique of how a section is written (paragraph progression, lead sentences, flow) rather than what it claims. Fire it: "analyze the writing quality of this section."

    /academic — heavyweight orchestrator across several dimensions at once

    When a task spans review + polish + figures + bibliography together. Reach for the individual skills when it doesn't; reach for this when it does. Fire it: /academic (or it engages when you're working across a paper).

    Review & critique¶

    adversarial-review — hostile pre-ship review of any artefact

    The default before shipping anything (figure, plan, code, draft). Independent agents tasked to find flaws, graded HALT/HIGH/MEDIUM/LOW — not reassurance. See Reviewing with adversarial agents. Fire it: "run an adversarial review of this."

    /review-paper — full 6-agent pre-submission referee report

    A journal-grade referee panel (contribution, identification, consistency, maths, tables, claims) for a finished paper targeting a named journal. Fire it: /review-paper.

    /review-paper-light — ~1-minute pre-screen

    A fast 2-agent check (contribution + identification) to decide whether a paper is ready for the full report. Run it first. Fire it: /review-paper-light.

    /review-grant — 6-agent funder-panel review

    A pre-submission panel review of a grant proposal for a specified funder. Fire it: /review-grant.

    /review-r — reviews existing R scripts

    Checks R code already on disk for quality, reproducibility, and correctness. Does not write new scripts. Fire it: /review-r.

    /review-stata — reviews existing Stata .do files

    The Stata counterpart to /review-r: 12-category review of existing do-files. Fire it: /review-stata.

    bib-audit — catches hallucinated and broken references

    Dual-Claude audit of a .bib file for fabricated, chimeric, or malformed entries before you submit. Fire it: auto-triggers on .bib work, or ask to "audit the bibliography."

    Figures & diagrams¶

    real-data-figure — publication figures from real data

    Time series, choropleths, scatter, coefficient, lollipop — sourced from OWID, World Bank, V-Dem, UCDP, ACLED and friends, with OWID-style design. Fire it: "plot for from data."

    tikz-figure — TikZ diagrams

    DAGs, mechanism diagrams, game trees, decision trees, flowcharts — built and compile-tested. Also debugs failed TikZ compiles. Fire it: "make a DAG / mechanism diagram of …"

    simulation-figure — Monte Carlo & parameter explorations

    Shows how an estimator breaks under assumption violations (weak IV, parallel- trends, staggered DID). Produces a static PDF + an interactive HTML. Fire it: "simulate what happens when …" / "show when this method fails."

    /coef-plot — one coefficient/event-study plot from a saved fit

    Atomic plot from a saved regression (.rds) or fresh estimation. (For a plot hand-entered from a paper's table, use real-data-figure.) Fire it: /coef-plot.

    Data, tables & analysis¶

    data-catalog — find and retrieve empirical data sources

    Catalogue + search + download for economics / political-economy / conflict data, outside a lecture context. Fire it: "find data on …" / "download ."

    /descriptives — publication-ready descriptive & balance tables

    Summary stats, treatment-vs-control balance, distribution/missingness diagnostics. Fire it: /descriptives.

    /regression — estimate one specification

    A single regression (or a small column-stack of related specs) for analysis. Fire it: /regression.

    /data-analysis — full R analysis pipeline (umbrella)

    Spans exploration → cleaning → regression → publication-ready tables and figures. The big one; the atomic skills above are its parts. Fire it: /data-analysis.

    build-fragment-table — paper-ready regression tables

    Both halves of Kai's outline-in-paper + fragment-from-code pattern (no stars; coef / [SE] / {p}; Mean-Control + N rows). Pairs with the exhibits workflow. Fire it: "build the table for this regression."

    /build-data-source-table — data-sources appendix table

    Generates the LaTeX data-sources table from the datasets: block of your replication metadata (the YAML is the source of truth). Fire it: /build-data-source-table.

    sync-codebook — keep survey + derived codebooks in sync

    Two-codebook (survey-frozen + derived-live) synchronization for survey + analysis projects. Fire it: /sync-codebook.

    stata-replication — end-to-end Stata replication pipeline

    Scaffolds the canonical 00_setup / 01_cleaning / 02_analysis triad per the one-canonical-script rule. Fire it: auto-triggers on Stata replication work.

    Bibliography & citations¶

    /sync-bib — refresh references.bib from Zotero

    Rebuilds the ZOTERO zone of your .bib and flags orphan citations in the .tex. Read-only against Zotero — safe for anyone to run. Fire it: /sync-bib.

    /add-cite-from-zotero — add one reference

    Pulls a single BibTeX entry from Zotero into the manual zone of references.bib without changing your global setup. Fire it: /add-cite-from-zotero <query-or-citekey>.

    /suggest-jel — JEL classification codes

    3-5 suggested JEL codes (primary first) for a paper or proposal. Fire it: /suggest-jel (paste the abstract).

    lit-review — structured literature search + synthesis

    Search, thematic clustering, citation extraction, and gap identification. Fire it: "do a literature review on …"

    lit-corpus — turn a folder of PDFs into a markdown corpus

    Converts academic PDFs into a token-efficient corpus for literature work. Fire it: "build a corpus from these PDFs."

    /sync-pdfs — pull cited PDFs from Zotero

    Copies PDFs from local Zotero storage into literature/ for every citekey in the project's bib. Fire it: /sync-pdfs.

    Project setup & hygiene¶

    /bootstrap-project — day-1 setup for a new or messy project

    Scaffolds the canonical folders + CLAUDE.md + .gitignore; asks project mode, collaborators, code stack. Fire it: /bootstrap-project in the project folder.

    bootstrap-paper — scaffold a new paper in house style

    A LaTeX paper skeleton in Kai's conventions (preamble, sections, bib zones). Fire it: "scaffold the paper skeleton."

    /refactor-structure — reorganize the folder/file layout

    Surveys the layout against the canonical structure and proposes a safe, confirm-each-step refactor (never deletes). Back up first. Fire it: /refactor-structure (read-only plan; --apply to act).

    /restructure-project — reorganize CLAUDE.md content

    The content counterpart to /refactor-structure (which does the folders). Fire it: /restructure-project.

    /housekeeping — read-only project audit

    Flags drift, stragglers, and hygiene issues without changing anything. Fire it: /housekeeping.

    /git — conversational git for non-experts

    Plain-language git help — describe what you want, no commands to memorise. Fire it: /git (or just describe the git situation).

    check-clone-discipline — confirm you're in your own clone

    On multi-clone projects, checks you're standing in your clone_<XX>/ before any git write. Cheap insurance against the shared-root hazard. Fire it: auto, at session start on multi-clone projects.

    /overleaf-sync — resolve Overleaf↔GitHub conflicts

    Diagnoses and recommends fixes for sync conflicts (often post-restructure). Fire it: /overleaf-sync.

    Workflow helpers — /check-rules · /new-sprint · /plan-status · /learn

    Small hygiene commands: re-read the active rules; start a fresh sprint plan; report sprint status; append a one-line memory correction. Fire them: type the /name.

    Replication & reproducibility¶

    init-replication — scaffold the replication package

    Adds replication_metadata.yaml + 00_setup scripts + a paper/README placeholder to an existing project. Fire it: "set up the replication package."

    audit-reproducibility — check the paper's numbers against the code

    Cross-checks numeric claims in the manuscript against actual R/Stata/Python outputs. A pre-submission gate. Fire it: "audit reproducibility of this paper."

    /audit-exhibits — provenance manifest for every exhibit

    Classifies each file in output/ as CODE-REPRODUCED / EXTERNAL / MANUAL / ORPHAN; --strict fails on any orphan. Fire it: /audit-exhibits.

    Talks¶

    research-presentation — design academic talks

    Conference, seminar, job-market, brown-bag talks — architecture by length, intro design, identification defense, slide rhetoric. Fire it: "design my seminar / JMP / conference talk."

    Cross-session coordination¶

    /coord — a message channel between your own sessions

    Lets your Claude Code sessions in different project folders leave each other messages (single user, many projects — not team chat). Fire it: /coord <verb> or "check coord."
